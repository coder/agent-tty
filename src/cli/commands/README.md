# src/cli/commands

## Overview

This directory holds one handler module per agent-tty CLI command. `src/cli/main.ts` registers the commands and calls these `run<Name>Command` functions with a `CommandContext`. The input and control commands (`type`, `paste`, `run`, `send-keys`, `mouse`, `mark`, `resize`, `signal` and `batch`) find the session with `resolveCommandTarget`. `inspect`, `wait`, `snapshot`, `screenshot`, `record export` and `record diff` read the manifest directly with `readManifestIfExists`. Session commands send an RPC to the session host socket through `sendRpc` (`src/host/rpcClient.ts`). `snapshot`, `screenshot` and render-mode `wait` fall back to offline replay when the host is unreachable. Every handler except `dashboard` (and non-JSON `skills get` and `skills path`, which write with `process.stdout.write`) writes its result through `emitSuccess` (`src/cli/output.ts`). Most command option interfaces are module-private. The result types mostly come from `src/protocol/messages.ts`.

## Invariants

- `gc` does not delete a session whose status is not collectable after `reconcileSession`. It skips it with the reason `session host is still alive`. [gc.ts:gcSessions]
- Before each delete, `gc` re-reads the manifest. If the status is no longer collectable, it skips the session (`session restarted between check and delete`). If the read fails, it skips it (`failed final manifest safety check`). [gc.ts:gcSessions]
- `gc` calls `forgetHome` only outside dry-run mode. [gc.ts:runGcCommand]
- `parseDurationToMs` trims the value, then accepts only input matching `/^([1-9]\d*)([mhd])$/`. Other input throws `INVALID_DURATION`. [gc.ts:parseDurationToMs]
- `signal` accepts only the signals in `ALLOWED_SIGNALS`. Other values throw `INVALID_SIGNAL`. [signal.ts:runSignalCommand]
- `resize` throws `INVALID_DIMENSIONS` unless `cols` and `rows` are positive integers. [resize.ts:runResizeCommand]
- `type`, `paste`, `send-keys`, `mouse` and `mark` validate the host reply with the matching result schema. A mismatch throws `PROTOCOL_ERROR`. [type.ts:runTypeCommand] [paste.ts:runPasteCommand] [send-keys.ts:runSendKeysCommand] [mouse.ts:runMouseCommand] [mark.ts:runMarkCommand]
- `mouse` validates its options with `MouseParamsSchema` before it resolves the session, so a malformed `--row` or `--col` is `INVALID_INPUT` with command `mouse`. [mouse.ts:runMouseCommand]
- Text input and `--file` are mutually exclusive. The file must be a regular file per `lstat` and at most `MAX_INPUT_FILE_SIZE` bytes. Violations throw `INVALID_INPUT`. [inputSource.ts:resolveCommandInputText]
- `wait` rejects a mix of legacy flags (`--exit`, `--idle-ms`) and render flags. `--text` and `--regex` are mutually exclusive. The default timeout is `DEFAULT_WAIT_TIMEOUT_MS` (30,000 ms), which the `main.ts` help text names. An `--idle-ms` at or above the effective timeout (explicit or default), or a `--screen-stable-ms` whose `screenStableMinimumMs` is not shorter than it, throws `INVALID_DURATION`. `--timeout 0` skips the check. [wait.ts:runWaitCommand] [wait.ts:assertWindowFitsTimeout] [main.ts:main]
- A timed-out `wait` throws `WAIT_TIMEOUT` with the wait result attached, so its error envelope keeps `result`. Without `--json`, and only when the wait lasted its whole timeout (`timeoutMs > 0`, measured by the CLI), the message names the timeout and, for the default, how to change it. With `--json`, the message stays `Wait timed out before its condition was met.` The host sends `eventLogStop` with the result of a render wait that timed out. When it does, in both modes the message ends with `The event log stopped at seq <n> (<byte limit|event limit|reason unknown>), so output after it is not seen.` and `details.eventLogStop` carries `{ reason, seq }`. The CLI never rereads the event log for a wait. `--idle-ms` and `--exit` waits carry no stop. When the host is unreachable, `wait` replays the stored log. A wait that the replayed screen does not satisfy fails with `REPLAY_ERROR`, and its message and `details.eventLogStop` carry the stop that `findEventLogStop` finds in the replayed events. [wait.ts:throwIfTimedOut] [wait.ts:timeoutMessage] [wait.ts:buildOfflineRenderWaitResult]
- `snapshot` and `screenshot` try the live RPC only when the manifest status is `running`. They fall back to offline replay only on `HOST_UNREACHABLE` and rethrow other errors. [snapshot.ts:runSnapshotCommand] [screenshot.ts:runScreenshotCommand]
- `record export` accepts only the formats in `RecordExportFormatSchema` (`asciicast`, `webm`, `svg`). `--animate` needs `svg`, and `svg` refuses `--timing`. An event log over the size limit fails with `EXPORT_ERROR` in every format, a message that names the log size and the limit, and `eventLogBytes` and `maxEventLogBytes` in `details`. A `webm` replay whose renderer makes no progress for the stall window fails with `EXPORT_ERROR`, a message that names the window and the last event that the replay reached, and `stallWindowMs`, `lastSeq` and `timingMode` in `details`. A `GhosttyWebCrashedError` from a WebM export fails with `EXPORT_ERROR` and adds its message to the fixed message. [record-export.ts:runRecordExportCommand]
- `batch` parses the whole plan with `parseBatchPlan` before it resolves the session target. [batch.ts:runBatchCommand]
- `create` polls readiness with an `inspect` RPC every `READINESS_POLL_INTERVAL_MS` (100 ms) for as long as the host process that it spawned runs (`hostRuns`). A probe that fails with `HOST_UNREACHABLE`, `HOST_TIMEOUT` or an `RPC_ERROR` whose cause is `EPIPE` (the host closed its server as the probe connected, as a host does whose program has already exited) counts as not ready yet (`isClosedByHost`). `create` rethrows that last error as soon as the host process has exited, and after `READINESS_DEADLINE_MS` (30 s) in any case. Any other error ends the wait at once. It checks the host process before it reads the manifest, so a session that exited before the host did is a result, not an error. [create.ts:waitForReadyHost]
- `doctor` reports the `node-runtime` check as failed when the Node version is outside the `engines.node` range of `package.json`. It keeps running the other checks, reports `ok: false` and sets `process.exitCode = 1`. [doctor.ts:runNodeRuntimeCheck] [doctor.ts:runDoctorCommand]
- `dashboard` throws `INVALID_INPUT` unless stdin and stdout are both TTYs. It also throws `INVALID_INPUT` when the libghostty-vt probe reports the renderer unavailable. [dashboard.ts:runDashboardCommand] [src/renderer/readiness.ts:assertDashboardRendererAvailable]
- `version` reports the constant `PROTOCOL_VERSION` (`'0.1.0'`). [version.ts:buildVersionResult]

## Side Effects

- Session commands send RPCs over the session socket through `sendRpc`. The method names are `run`, `type`, `paste`, `sendKeys`, `mouse`, `mark`, `resize`, `signal`, `snapshot`, `screenshot`, `wait`, `waitForRender` and `inspect`. `create` also sends `inspect` while it polls. [run.ts:runRunCommand] [send-keys.ts:runSendKeysCommand] [wait.ts:runWaitCommand] [create.ts:runCreateCommand]
- `create` calls `allocateSession` (`src/host/lifecycle.ts`) with a `launch` callback that records the session ID and starts the host process through `launchHost`. If `launchHost` or a later step of `allocateSession` throws, `create` removes the session directory with `fs.rm`. A bad `cwd`, shell path or command segment fails before `allocateSession` creates the directory, so no session directory is left behind. A failure between `mkdir` and the callback, such as a failed `chmod`, leaves the empty session directory in place. Any failure after `allocateSession` returned, a failed readiness poll included, writes the empty `create-failed` marker with `writeCreateFailedMarker` and logs a failed marker write at debug level (`writeMarkerOrLog`). On Windows, while that write fails, the manifest names no program and the host runs (`hostRuns`, where a probe that throws counts as an exited host), it writes the marker again every 100 ms, up to 50 times, and reads the manifest after each write. It then calls the host's `stop()` (on Windows only once the manifest names the program) and leaves the session directory in place. `create` rethrows the error with `details.sessionId` added, and an error that is not a `CliError` becomes `INTERNAL_ERROR`. In text mode it first writes `Session <id> failed to start.` to stderr with `writeHumanErrorLines`. It registers the Home through `upsertHome`. [create.ts:runCreateCommand] [create.ts:writeMarkerOrLog] [create.ts:hostRuns]
- `gc` reads session directories, calls `reconcileSession` (which can rewrite manifests), deletes collectable session directories with `fs.rm` outside dry-run mode, and deregisters Homes through `forgetHome`. [gc.ts:gcSessions] [gc.ts:runGcCommand]
- `inspect` calls `reconcileSession` when the host is unreachable, and for an ended session other than destroyed whose folder holds the destroy marker. When that repair throws, it shows the manifest as it reads. It reads `eventCount`, `eventLogBytes` and `eventLogStop` in one pass over `events.jsonl` with `scanEventLog`, for a live host and for offline replay alike, so `eventLogStop.seq` is never above `lastEventSeq`. It leaves `eventLogStop` out when the log holds no stop marker. Without `--json`, an `Event Log Stopped:` line follows `Event Log Bytes:`. [inspect.ts:runInspectCommand] [inspect.ts:formatSessionLines] [src/storage/eventLogCodec.ts:scanEventLog]
- `destroy` and `list` call `destroySession` and `listSessions` from `src/host/lifecycle.ts`. [destroy.ts:runDestroyCommand] [list.ts:runListCommand]
- `snapshot`, `screenshot`, `wait` and `record diff` run offline replay through `withOfflineReplayRenderer` (`src/replay/offlineReplay.ts`). `record diff` sends no RPC. [wait.ts:runOfflineRenderWait] [record-diff.ts:runRecordDiffCommand]
- Offline `snapshot` and `screenshot` write artifact files into the session artifacts directory and append artifact-manifest entries through `publishArtifactWithRollback` (`src/storage/artifactManifest.ts`). `snapshot` writes a temp JSON file through `writeTextFileAtomic`, and `screenshot` gets a temp PNG from the renderer. `publishArtifactWithRollback` links or copies the temp file into place without replacing an existing file. [src/snapshot/capture.ts:captureSnapshotResult] [src/snapshot/capture.ts:persistSnapshotArtifact] [src/screenshot/capture.ts:captureScreenshotResult]
- `record export` writes to the session artifacts directory (created through `ensureArtifactsDir` when missing) or, with `--out`, to any writable user path outside the session. Every format finishes with a rename over the target path, so a symlink at `--out` is replaced, not followed. [record-export.ts:resolveOutputPath]
- `screenshot --out` resolves the path before it captures, then copies the published in-session PNG to it and returns that path as `artifactPath`. A path it cannot resolve or write, or a path inside the Home's `sessions/` folder, fails with `EXPORT_ERROR`. A session folder removed before the copy fails with `SESSION_NOT_FOUND`. When the copy fails and the session folder still exists, it removes the capture's manifest entry and file through `removeArtifactEntry`, and ignores an error of that removal. [screenshot.ts:runScreenshotCommand]
- `record export` writes asciicast and svg files through `writeTextFileAtomic`, renders svg with `captureGridFrames` (`src/replay/gridFrames.ts`) and `renderGridFramesToSvg` (`src/export/svg.ts`), delegates webm to `generateWebmExport` (`src/export/webm.ts`), and appends an artifact-manifest entry through `appendArtifactWithRollback` with the exported file's `outputFileIdentity` (for webm, the temp file's, which the rename keeps), so the entry of an earlier export to the same file goes. [record-export.ts:runRecordExportCommand]
- `doctor` creates and removes temporary files, a temporary session directory and a socket. Through `ensureHome` it creates the Home directory (mode 0700) and its `sessions/` directory when they are missing, and leaves them in place. [src/storage/home.ts:ensureHome] [doctor.ts:runHomeWritableCheck] It spawns a PTY through `createPty`, dynamically imports `playwright` and `ghostty-web`, and launches headless Chromium [doctor.ts:runBrowserLaunchCheck]. It sets `process.exitCode = 1` when a check fails. [doctor.ts:runDoctorChecks] [doctor.ts:runPtySpawnCheck] [doctor.ts:runDoctorCommand]
- `batch` installs `SIGINT` and `SIGTERM` handlers. On a signal it writes a partial envelope synchronously and calls `process.exit`. [batch.ts:executeWithInterruptFlush]
- When a step fails, `batch` sets `process.exitCode`. With `--keep-going` the code is 1. Without it, the code is `exitCodeForError` of the first failed step's error code. Without `--keep-going` and with `--json`, it emits an error envelope with the failed step's code and message and the per-step results as `result`. Otherwise it emits a success envelope. [batch.ts:runBatchCommand]
- `version --json` runs `discoverCapabilities('quick')`, which dynamically imports `playwright` and libghostty-vt. If discovery fails, it writes a warning to stderr and omits `capabilities`. [version.ts:buildVersionResult] [src/renderer/capabilities.ts:discoverCapabilities]
- `type`, `paste`, `run` and `batch --file` read input files with `lstat`, `stat` and `readFile`. [inputSource.ts:resolveCommandInputText] [batch.ts:resolveBatchSource]
- `dashboard` lazily imports `src/dashboard/app.tsx` and runs the interactive app. [dashboard.ts:runDashboardCommand]
