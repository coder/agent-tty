# evals/lib

## Overview

Shared library code for the eval harness lanes (prompt, execution, dogfood). It holds the eval data model (TypeScript types and matching Zod schemas), the prompt scoring and anti-pattern detection logic, dogfood bundle scoring, the condition matrix and comparison metrics, statistics helpers, JSON and Markdown report generation, run artifact storage, token aggregation, a concurrency scheduler, and a harness that runs the repo CLI. Most modules are pure. File I/O is limited to `artifacts.ts`, `cliHarness.ts` and `bundleScoring.ts`.

## Interface

- `[types.ts:ExpectedSkill]`, `[types.ts:SkillCondition]`, `[types.ts:EvalLane]`, `[types.ts:VerifierKind]`, `[types.ts:AntiPatternSeverity]`, `[types.ts:ProviderMode]`: string-union type aliases for skills (`none`/`agent-tty`/`dogfood-tui`), conditions (`none`/`self-load`/`preloaded`/`stale`), lanes (`prompt`/`execution`/`dogfood`), verifier kinds, severities and provider modes.
- `[types.ts:PromptEvalCase]`, `[types.ts:ExecutionEvalCase]`, `[types.ts:DogfoodEvalCase]`, `[types.ts:EvalCase]`: per-lane case definitions discriminated by a literal `lane` field. `EvalCase` is their union. Related building blocks: `SetupStep`, `VerifierSpec`, `WorkflowCheck`, `AntiPatternRule`, `ArtifactRequirement`, `ReportRequirement`, `ScoreComponent`, `ScoreBreakdown`.
- `[types.ts:EvalResult]`, `[types.ts:RunMetadata]`, `[types.ts:AggregateMetrics]`, `[types.ts:ComparisonMetrics]`, `[types.ts:MatrixEntry]`, `[types.ts:JsonReport]`, `[types.ts:BaselineComparison]`, `[types.ts:TokenReportSummary]`: result, run, aggregate, comparison and report shapes. The file also exports the score and check result shapes (`PatternMatchResult`, `ForbiddenPatternResult`, `AntiPatternFinding`, `WorkflowCheckResult`, `BundleCompletenessScore`, `ReportCompletenessScore`, `EvidenceQualityScore`, `PromptCaseScore`), condition summaries (`ConditionAggregateSummary`, `ConditionComparisonSummary`), trial and baseline shapes (`ConfidenceInterval`, `TrialAggregation`, `PerCaseComparison`, `BaselineOverall`), `ProviderComparisonReport`, and the CLI harness shapes `EvalCliOptions`, `EvalCliResult` and `EvalEventRecord`. Provider adapter shapes (`ProviderPromptRequest`, `ProviderAgentResult`, `NormalizedProviderOutput`, `ProviderConfig`, `TokenUsage` and others) live in the same file.
- `[types.ts:buildWorkItemKey]`: returns `lane:caseId:condition:trial` for an `EvalWorkItemIdentity`. `[types.ts:assertUniqueWorkItems]` throws on the first duplicate key.
- `[schemas.ts:EvalCaseSchema]`: Zod discriminated union on `lane` over `PromptEvalCaseSchema`, `ExecutionEvalCaseSchema` and `DogfoodEvalCaseSchema`. The file also exports enum schemas (`EvalLaneSchema`, `SkillConditionSchema`, `ExpectedSkillSchema`, `ProviderModeSchema` and others).
- `[schemas.ts:EvalResultSchema]`, `[schemas.ts:RunMetadataSchema]`, `[schemas.ts:JsonReportSchema]`, `[schemas.ts:AggregateMetricsSchema]`, `[schemas.ts:BaselineComparisonSchema]`, `[schemas.ts:TokenReportSummarySchema]`: result, run, aggregate and report schemas. The file also exports an object schema for each building block and score shape: `SetupStepSchema`, `VerifierSpecSchema`, `WorkflowCheckSchema`, `AntiPatternRuleSchema`, `ArtifactRequirementSchema`, `ReportRequirementSchema`, `PatternMatchResultSchema`, `ForbiddenPatternResultSchema`, `AntiPatternFindingSchema`, `WorkflowCheckResultSchema`, `ScoreBreakdownSchema`, `ReportCompletenessScoreSchema`, `EvidenceQualityScoreSchema`, `ComparisonMetricsSchema`, `PromptCaseScoreSchema`, `ProviderCapabilitiesSchema`, `ProviderRuntimeInfoSchema`, `ConditionAggregateSummarySchema`, `ConditionComparisonSummarySchema`, `ProviderComparisonReportSchema`, `ConfidenceIntervalSchema`, `TrialAggregationSchema`, `PerCaseComparisonSchema`, `BaselineOverallSchema` and `EvalCliOptionsSchema`.
- `[schemas.ts:ProviderConfigSchema]`, `[schemas.ts:ProviderPromptRequestSchema]`, `[schemas.ts:ProviderAgentRequestSchema]`, `[schemas.ts:NormalizedProviderOutputSchema]`, `[schemas.ts:TokenUsageSchema]`: provider adapter schemas. `[schemas.ts:EvalCliResultSchema]` validates CLI harness results. `[schemas.ts:EvalEventRecordSchema]` re-exports `EventRecordSchema` from `src/protocol/schemas.ts`.
- `[schemas.ts:EvalCaseSchemaType]` and the other `*SchemaType` exports: `z.infer` aliases. The `_*SchemaParity` exports are `AssertExact` aliases between `types.ts` and the schemas. Each resolves to `true` on a match and to `never` on drift.
- `[scoring.ts:scorePromptCase]`: scores a prompt-lane response (0.4 pattern coverage, 0.4 skill selection, 0.2 workflow, minus penalties for forbidden matches and anti-pattern findings, clamped to [0,1]). `[scoring.ts:PASS_THRESHOLD]` is 0.6.
- `[scoring.ts:compilePattern]`, `[scoring.ts:matchPatterns]`, `[scoring.ts:checkForbiddenPatterns]`, `[scoring.ts:checkWorkflow]`: regex compilation (cached), pattern matching with 1-based line numbers, negation-aware forbidden-pattern checks, and workflow checks with `dependsOn`.
- `[scoring.ts:computeAggregateMetrics]`, `[scoring.ts:computePrecisionRecall]`, `[scoring.ts:isInNegationContext]`, `[scoring.ts:inferSelectedSkill]`: aggregate metrics, precision/recall/F1, negation detection, and skill inference from response text.
- `[antiPatterns.ts:DEFAULT_ANTI_PATTERN_RULES]`: 7 rules (`blind-sleep`, `tmux-usage`, `screen-usage`, `adhoc-screenshot`, `missing-json-flag`, `orphaned-session`, `direct-manifest-write`).
- `[antiPatterns.ts:detectAntiPatterns]`: scans a transcript line by line for most rules. It scans `orphaned-session` and `missing-json-flag` over the whole transcript, and `missing-json-flag` gives at most one finding. It returns deduplicated findings sorted by line number, then rule id. Helpers: `[antiPatterns.ts:buildScannableTranscript]`, `[antiPatterns.ts:countAgentTtyCalls]`, `[antiPatterns.ts:compileAntiPatternRegex]`, `[antiPatterns.ts:filterRulesBySeverity]`, `[antiPatterns.ts:summarizeFindings]`.
- `[bundleScoring.ts:scoreBundleCompleteness]`, `[bundleScoring.ts:scoreReportCompleteness]`, `[bundleScoring.ts:scoreEvidenceQuality]`: dogfood-lane scores for bundle checks, report section coverage and evidence quality.
- `[matrix.ts:SKILL_CONDITIONS]`: frozen ordered tuple `none`, `self-load`, `preloaded`, `stale`.
- `[matrix.ts:buildConditionMatrix]`: builds case × condition × provider `MatrixEntry` rows. `[matrix.ts:groupResultsByCase]`, `[matrix.ts:groupResultsByCondition]`, `[matrix.ts:groupResultsByProvider]` group results. `[matrix.ts:computeComparisonMetrics]` computes skill lift, routing gap, stale-skill harm and related metrics per (provider, lane, case).
- `[statistics.ts:computeMean]`, `[statistics.ts:computeStdDev]`, `[statistics.ts:computeConfidenceInterval]`, `[statistics.ts:computePassRate]`, `[statistics.ts:computePairedDelta]`, `[statistics.ts:computeWinRate]`, `[statistics.ts:bootstrapPairedCI]`: mean, sample standard deviation, t/z confidence intervals, Wilson pass-rate interval, paired deltas, win rates and a seeded percentile bootstrap.
- `[reporting.ts:generateJsonReport]`: builds the JSON report with aggregates, condition and provider comparisons, trial aggregation, baseline and token sections. It validates the core report with `JsonReportSchema`. The returned object also carries `aggregateMetrics`, `laneSummaries`, `providerComparisons` and `resultRefs`, which the strict schema rejects. `[reporting.ts:generateMarkdownReport]` renders the same data as Markdown.
- `[reporting.ts:buildBaselineComparison]`: pairs baseline and candidate results and returns per-case and overall deltas with verdicts `improved`, `regressed` or `inconclusive`. `[reporting.ts:generateProviderComparison]` and `[reporting.ts:formatSummaryTable]` build provider-pair reports and a one-row Markdown summary table.
- `[artifacts.ts:EvalArtifactStore]`: run artifact store rooted at a base directory that it resolves to an absolute path. Layout: `<runId>/<caseId>/{transcript.txt,result.json}` and `<runId>/metadata.json`.
- `[artifacts.ts:writeTokenUsageArtifact]`: writes `<artifactsDir>/<lane>/<caseId>/<condition>/token-usage.json`. `[artifacts.ts:TokenUsageArtifact]` and `[artifacts.ts:WriteTokenUsageArtifactParams]` are its types.
- `[artifacts.ts:validatePathSegment]`: asserts a non-empty path segment that is not `.` or `..` and has no `/`, `\` or NUL. `[artifacts.ts:generateRunId]` returns `eval-YYYYMMDD-HHMMSS-<6 hex>`.
- `[tokenAggregation.ts:aggregateTokenRecords]`: sums `RawTokenRecord` usage into a `TokenReportSummary` (grand total, per lane, per case). Returns `undefined` for no records.
- `[scheduler.ts:runScheduled]`: runs an executor over items with a bounded worker count and returns settlements in input order. Types: `ScheduledWorkItem`, `SchedulerItemSettlement`, `SchedulerOptions`, `SettledResult`.
- `[cliHarness.ts:runEvalCli]`: runs `src/cli/main.ts` through `node --import tsx`, adds `--json` by default, and returns a validated `EvalCliResult`.
- `[cliHarness.ts:createIsolatedEvalHome]`, `[cliHarness.ts:materializeEvalWorkspace]`, `[cliHarness.ts:cleanupEvalHome]`: create a temp `AGENT_TTY_HOME`, copy a workspace template and run bootstrap commands into it, and remove it after killing session processes.
- `[cliHarness.ts:createEvalSession]`, `[cliHarness.ts:destroyEvalSession]`, `[cliHarness.ts:readEvalEvents]`, `[cliHarness.ts:fixtureCommand]`: create and destroy a CLI session, read and validate its `events.jsonl`, and build a command for a `test/fixtures/apps/<name>/main.ts` app.

## Invariants

- `[schemas.ts:EvalCaseSchema]` and the other object schemas in `schemas.ts` call `.strict()` and reject unknown keys.
- `[schemas.ts:ExecutionEvalCaseSchema]` requires at least one condition, at least one verifier, and a fixture or a target. `[schemas.ts:DogfoodEvalCaseSchema]` requires at least one condition, one bundle requirement, and an artifact or report requirement. `[schemas.ts:PromptEvalCaseSchema]` requires at least one expected pattern.
- `[schemas.ts:ScoreComponentSchema]` rejects `score > maxScore`. `[schemas.ts:AggregateMetricsSchema]` requires `passed + failed === totalCases`. `[schemas.ts:BundleCompletenessScoreSchema]` requires `passed + failed === totalChecks`.
- `[schemas.ts:addTimestampOrderIssue]` rejects `completedAt` earlier than `startedAt` in `EvalResultSchema`, `ProviderPromptResultSchema` and `ProviderAgentResultSchema`.
- `[schemas.ts:_EvalCaseSchemaParity]` and the other `_*SchemaParity` types resolve to `never` when `types.ts` and the schemas diverge. Exporting a `never` alias compiles, and nothing in the repo uses these types, so drift does not fail the typecheck.
- `[types.ts:buildWorkItemKey]` throws on an empty `caseId` or a trial that is not a positive integer.
- `[scoring.ts:PROMPT_SCORE_WEIGHTS]` is checked at module load: the weights must sum to 1. `[scoring.ts:checkWorkflow]` throws on a duplicate workflow check id.
- `[scoring.ts:scorePromptCase]` sets `passed` only when the total score is at least `PASS_THRESHOLD` and the inferred skill is correct.
- `[antiPatterns.ts:validateRules]` runs at module load on `DEFAULT_ANTI_PATTERN_RULES`. It throws on empty fields, an unknown severity, no patterns, a duplicate id, or a pattern that does not compile.
- `[statistics.ts:bootstrapPairedCI]` throws unless iterations is an integer of at least 100. `[statistics.ts:DEFAULT_BOOTSTRAP_SEED]` is 42, so results are reproducible. `[statistics.ts:assertPairedLengths]` throws when paired arrays differ in length.
- `[matrix.ts:buildConditionMatrix]` throws on empty or duplicate provider ids and validates each entry with `MatrixEntrySchema`. `[matrix.ts:assertComparableGroup]` throws when a group mixes providers, cases or lanes.
- `[reporting.ts:assertMetadata]` throws on an empty `runId` or non-array providers, lanes or conditions. `[reporting.ts:generateJsonReport]` validates the core report with `JsonReportSchema`.
- `[reporting.ts:buildBaselineComparison]` throws when baseline and candidate share no `caseId:condition` group or when paired trial counts differ.
- `[artifacts.ts:assertPathInsideBase]` asserts resolved paths stay inside the base directory. `[artifacts.ts:EvalArtifactStore]` resolves a relative base directory against the cwd, and requires matching `runId`/`caseId` on saved results.
- `[tokenAggregation.ts:accumulateTokenUsage]` throws on token counts that are not non-negative integers.
- `[scheduler.ts:runScheduled]` throws unless concurrency is a positive integer. A rejected executor becomes a `rejected` settlement. An error in `onItemStart` propagates. An error from `onItemFinish` after a fulfilled executor replaces that settlement with a `rejected` one and calls `onItemFinish` again. An error from that second call, or from `onItemFinish` after a rejected executor, propagates.
- `[cliHarness.ts:normalizeTempHome]` makes `cleanupEvalHome` throw unless the home is inside or equal to `os.tmpdir()`. It accepts the temp root itself, so `cleanupEvalHome(os.tmpdir())` would delete the whole system temp directory. `[cliHarness.ts:fixtureCommand]` throws unless the app name matches `SAFE_FIXTURE_APP_NAME_PATTERN`.
- `[cliHarness.ts:runEvalCli]` throws on a non-absolute `home` and validates its result with `EvalCliResultSchema`. The default timeout is `DEFAULT_CLI_TIMEOUT_MS` (30,000 ms).

## Side Effects

- `[artifacts.ts:EvalArtifactStore]` creates directories with `fs.mkdir` and writes through `writeTextFileAtomic` and `writeValidatedJsonFile` from `src/storage/manifests.ts`. It reads with `readValidatedJsonFile`. `loadResults` also calls `fs.stat` and `fs.readdir` on the run directory.
- `[artifacts.ts:writeTokenUsageArtifact]` writes JSON through `writeValidatedJsonFile` from `src/storage/manifests.ts`. `[artifacts.ts:warnSkippedResult]` calls `console.warn` for results it skips.
- `[artifacts.ts:generateRunId]` reads the clock and `node:crypto` `randomBytes`.
- `[cliHarness.ts:runEvalCli]` spawns `process.execPath` with `child_process.spawnSync` and sets `AGENT_TTY_HOME` in the child env. `[cliHarness.ts:materializeEvalWorkspace]` copies files with `fs.cp` and runs bootstrap commands with `spawnSync`.
- `[cliHarness.ts:createIsolatedEvalHome]` calls `fs.mkdtemp` under `os.tmpdir()`. `[cliHarness.ts:cleanupEvalHome]` reads session manifests, sends `SIGKILL` with `process.kill`, and removes the home with `fs.rm`.
- `[cliHarness.ts:createEvalSession]` starts a real agent-tty session host through `runEvalCli`. `[cliHarness.ts:readEvalEvents]` reads `events.jsonl` with `readFileSync`.
- `[bundleScoring.ts:scoreBundleCompleteness]` reads the bundle directory through `validateBundle` (`src/tools/validate-bundle.ts`) and `scanBundleArtifacts` (`src/tools/review-bundle.ts`). `[bundleScoring.ts:scoreEvidenceQuality]` reads it through `scanBundleArtifacts` only. `[bundleScoring.ts:readFileSizeIfPresent]` calls `fs.stat`.
- `[scoring.ts:COMPILED_PATTERN_CACHE]` is a module-level `Map` that `compilePattern` fills.
- `[scheduler.ts:runScheduled]` calls the optional `logLine` callback. It does no I/O itself.
- `reporting.ts`, `schemas.ts`, `types.ts`, `statistics.ts`, `matrix.ts`, `antiPatterns.ts` and `tokenAggregation.ts`: none found in code.
